The firewall lab

This page plays a legacy site — call it the Riverbend Gazette, last rewritten in 2009. Its stylesheet has unscoped element styles feeding wysiwyg tables, an #content template wrapper, and one !important from an old bug fix. Nothing is scoped, because that's the premise. Into this page we drop two component libraries: one that defends itself, one that doesn't.

The trick under test, from the web-component world:

my-table:not(#_) :is(table, caption, colgroup, col, thead, tbody, tfoot, tr, th, td) {
	all: revert;
}

:not(#_) matches everything and donates an id of specificity — (1,0,2) with the descendant part, no !important. all: revert rolls every property back past the author origin to UA defaults. Together: a specificity floor that wipes the host page's styling off the component's parts, so the library can re-state what it actually wants just above it.

3. The firewall: same page, defended

my-table runs the firewall, then re-states its real styles above the floor, reading only its own tokens. The dashes, stripes, uppercase, and green are gone. Two things still show, both by design of the platform, not failure of the trick: the Gazette's Georgia (inheritance passes through — legacy's table { font-size: 14px } was declared on the table and is blocked, but font-family inherits into it from body and flows right through), and the red italic caption — see the next section.

4. What beats the firewall — honestly

Two defeats, both visible below. The caption is still red italic: legacy's !important wins against any specificity, and revert is not important. And the cells are purple, letterspaced, and italic: site-tweaks.css reaches in with #late-zone my-table td — it ties the floor at (1,0,2) and loads after the library, so it wins on order. The floor is a floor, not a ceiling. The library can raise it (:not(#_#_)), the site can climb again — that arms race is why the firewall is the last rung of the ladder, not the first.

5. The sanctioned doors: tokens and modes

The firewall closes the selector door; the API stays open, because all doesn't touch custom properties. First table: the site repaints --table-* tokens on a wrapper (.branded-zone in site-tweaks.css) — no selector crosses the boundary, order doesn't matter, survives library updates. Second table: a data-mode attribute on the host element itself.

One footgun found building this page: the library's token defaults can't be declared on the host element, because a direct declaration beats anything inherited — the wrapper's repaint could never reach in. Defaults belong in the fallback slot of a private property: --_fill-header: var(--table-fill-header, #232336), with the component consuming --_fill-header. Public property = the API; private property = resolved value; fallback = the default.

6. The inversion: legacy content inside the component

The boundary cuts both ways, per element, not per subtree. The paragraph an editor pasted inside the component still wears the Gazette's styling — the firewall only names table parts. But the little table nested inside a cell gets captured and restyled as if it were the component's own: :is() can't tell whose table it is. If slotted foreign tables should keep their own look, the firewall needs a child-combinator leash, not a descendant net.

7. The ladder

Three ways out of this mess, best first:

  1. Fix the scoping. The original sin is table { } where .prose table { } belonged. Best fix, rarely affordable — it means auditing every template that emits wysiwyg content.
  2. Layer the legacy sheet. If you own the page: @import url('legacy.css') layer(legacy); — one line, no selector edited. Layered loses to unlayered regardless of specificity, so the component wins everywhere and the wysiwyg areas render exactly as before. No firewall needed at all.
  3. The firewall. When you own nothing but your own stylesheet. It holds against everything below its floor, and loses — honestly, visibly — to !important and to later-loading rules at or above the floor.

On every rung the exposed styling API stays the same: tokens and host attributes, never selectors. The escape hatches differ; the contract doesn't have to.
