Tailwind vs tokens

One component, written twice: once with semantic tokens (the PSSST way), once with real, idiomatic Tailwind — the way the docs and shadcn write it. Then we move both cards through the same contexts and watch what happens. Nothing here is a strawman; the Tailwind card is the card you'd actually write.

1. The default page

So far, no argument. Both cards look right, and the Tailwind one was probably faster to type. If pages never changed, this would be a tie.

2. A focused section

This band is <section data-emphasis='focused'> — one attribute. The kit repaints the token values for this scope (see settings.css). The two cards below are copy-pasted from band 1, byte for byte.

Nobody touched either card. One of them knew where it was. The token card reads its slots — --fill-secondary, --ink-primary, --accent — and the scope hands it new values. The Tailwind card's colors are welded to its markup, so it ignores its context and stays a white card from some other page.

3. The fix

Here's the Tailwind card repaired for this context: every color class swapped by hand. The token card is here too — still the same markup it had in band 1.

The fix works — and now there are two Tailwind cards. This one can never go back to band 1. Every context that can vary multiplies the markup: a second theme, a compact mode, a print style, each one is another hand-edited copy. (Tailwind's dark: variant doesn't escape this — it doubles the classes on every element instead, and only covers one axis.) The token card is still one card.

Now the change request every project eventually gets: “rebrand the accent color.” Token version: edit --accent, one line, every card in every context follows. Tailwind version: find every text-blue-600 — and every text-blue-400 in the forks — and decide, element by element, which ones meant accent and which ones just meant blue. The class name records the value but throws away the intent, and you can't grep for a design decision that was never named.

That's the whole argument. Tailwind constrains your values but not your choices; a design system is the opposite. Roughly 40 named tokens is the entire design surface here — small enough to hold in your head, small enough to repaint from above.
